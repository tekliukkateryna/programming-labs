### 3. Алгоритми

1. <b>Selection Sort</b>  
<u>Ідея</u>  
Масив умовно ділиться на дві частини: відсортовану та невідсортовану. На кожному кроці алгоритм знаходить найменший елемент у невідсортованій частині та міняє його місцями з першим елементом цієї частини.  
<u>Ключові етапи</u> 
- Прохід по невідсортованій частині масиву для знаходження мінімального значення.  
- Перестановка знайденого мінімуму з елементом, що стоїть на поточній позиції початку невідсортованої частини.  
- Просування межі відсортованої частини на один елемент вперед.Алгоритмічна складність  
<u>Алгоритмічна складність</u>  
Оскільки ми завжди проходимо весь залишок масиву для пошуку мінімуму, складність не залежить від початкового стану даних.   
Найгірший випадок: O(n^2) Найкращий випадок: O(n^2).  

2. Quick Sort (Схема Lomuto з рандомним pivot)  
<u>Ідея</u>  
Використовується стратегія "розділяй і володарюй". Ми вибираємо опорний елемент (pivot), переставляємо елементи так, щоб зліва були менші за нього, а справа — більші, і рекурсивно повторюємо це для обох частин.  
<u>Ключові етапи</u>  
- Вибір випадкового індексу в масиві та обмін його з останнім елементом. Це допомагає уникнути найгіршого випадку (коли опорний елемент (pivot) завжди виявляється найменшим або найбільшим у масиві, що призводить до вкрай нерівномірного поділу на частини).  
- Partitioning (Схема Ломуто):Використовується вказівник i, який позначає межу «менших» елементів.Проходимо циклом j по масиву. Якщо поточний елемент менший за pivot, i++ та міняємо елементи місцями.  
- Рекурсивний виклик для лівої та правої частин відносно pivot.  
<u>Алгоритмічна складність</u>
Найкращий/Середній випадок: O(nlog n) (коли півот ділить масив приблизно навпіл). Найгірший випадок: O(n^2) (якщо завжди обирається найменший або найбільший елемент, проте рандомізація робить це вкрай малоймовірним).  

3. Merge Sort (Bottom-up)  
<u>Ідея</u>
На відміну від рекурсивного підходу, цей варіант є ітеративним. Алгоритм розглядає масив як набір з підмасивів. На кожній ітерації він зливає сусідні пари підмасивів у більші впорядковані масиви (по 2 елементи, потім по 4, 8 і так далі), поки весь масив не стане одним цілим.  
<u>Ключові етапи</u>  
- Визначається розмір кроку (1, 2, 4, ...).  
- Злиття сусідніх блоків розміром у тимчасовий масив у правильному порядку.  
- Копіювання відсортованих блоків назад в основний масив.  
<u>Алгоритмічна складність</u>  
Merge sort гарантує стабільну швидкість незалежно від вхідних даних, але потребує додаткову пам'ять.  
Найгірший випадок: O(nlog n)  
Найкращий випадок: O(nlog n)

### 4. Використання

Selection sort:
- 1: Треба відсортувати дуже малу кількість елементів
- 2: Обмежений ресурс пам'яті. У мікроконтролерах, де пам'ять має обмежений цикл перезапису, важливо мінімізувати кількість переміщень елементів.  

Quick sort:
- 1: Стандартні бібліотеки мов програмування.
- 2: Системи обробки великих масивів чисел.

Merge sort:
- 1: Зовнішнє сортування (якщо всі дані не поміщаються в оперативну пам'ять).
- 2: Сортування зв'язаних списків (оскільки не потребує доступу по випадкових індексах).
