### 2. Особливості:  
На основі масиву фіксованого розміру:
+ Займає заздалегідь визначений обсяг пам'яті
+ Миттєвий доступ до елементі через індексацію
- однак не гручкий з точки зору пам'яті (може бути зарезервована зайва або навпаки не вистачати)  

На основі масиву змінного розміру:  
+ Гнучкий з точки зору пам'яті
+ Теж легкий доступ до елементів за індексом
- однак, коли місця стає замало то розширення займає певний час (створити умовно в 1.5 рази довший масив, туди скопіювати елементи, видалити попередній - це не так вже й швидко)

На основі зв'язного списку:  
+ Гнучкий з точки зору пам'яті, при чому пам'ять може бути виділена не одним цільним блоком, що добре, якщо такого блоку не знаходиться
+ немає періодичного копіювання елементів як у масиві змінного розміру
- однак додаткові витрати пам'яті на зберігання вказівників
- однак елемент за індексом ще треба було б пошукати і це займає суттєво більше часу 
### 3. Алгоритмічна складність

|Операція \ Реалізація| Array | ArrayList (Vector) | LinkedList |
|:--:|:--:|:--:|:--:|
|додавання на початок| O(n) | O(n) | O(1) |

2b  
- append O(1) (у вузлі є це вільне місце) або O(n) (вузол заповнений)  
- append_left O(n)  
- insert O(n/N+N) (насправді досить швидко, бо при пошуку "стрибаємо" блоками по N елементів)  
- erase O(n/N+N)  
- find_by_index O(n/N)  
- find_by_value O(n)  

PS. LinkedList у мене із вказівниками і на head, i на tail, тому так швидко
